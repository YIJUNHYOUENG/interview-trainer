# 화면 설계

2026-11-04 기준. [DESIGN.md](DESIGN.md) 5장을 화면 단위로 자세히 푼 문서이고, 모양은 [wireframes.html](wireframes.html) 을 브라우저로 열어 확인한다. 이 문서에서 설계와 달라지는 부분은 12장에 모아 두었다.

## 2. 공통 규칙

- **상단바**: 뒤로가기 + 제목. 홈에서는 뒤로가기를 쓰지 않는다. 진행 중인 면접·퀴즈는 뒤로가기를 눌러도 바로 나가지 않고 확인을 받는다.
- **서버 연결 상태**: 홈, 면접 홈에 점 + 글자("서버 연결됨" / "서버 꺼짐")로 표시한다. 앱 시작과 두 화면에 들어올 때 `/health` 를 부르며, 이 호출만 타임아웃을 3초로 짧게 둔다. 서버가 꺼져 있으면 AI 가 필요한 버튼("면접 시작", "분석")만 비활성으로 만들고 이유를 한 줄로 보여 준다. 개념 학습·퀴즈·오답노트·히스토리 열람은 항상 쓸 수 있다.
- **서버를 기다리는 화면**: 항상 "무엇을 기다리는지"를 문장으로 적는다("면접관이 생각 중이에요", "리포트를 만들고 있어요 · 약 20초"). 실패하면 같은 화면에서 재시도 버튼을 준다.
- **빈 상태**: 목록마다 한 줄 안내와 다음 행동 버튼을 둔다(예: "오답이 없어요 → 퀴즈 풀기").
- **방향**: 세로 고정(DESIGN 5장).
- **표시 규칙**: 숙련도는 별 5개(미학습은 빈 별 5개, "미학습"). 정답은 초록, 오답은 빨강, 선택·주요 버튼은 파랑. 상태를 색만으로 구분하지 않고 `✓`, `✕`, 글자를 같이 쓴다.
- **터치 영역**: 버튼과 목록 항목은 높이 48dp 이상.

## 3. 홈

| 영역 | 내용 | 이동 |
| --- | --- | --- |
| 상단 | 앱 이름, 서버 연결 상태 | |
| 영역 카드 2개 | "CS 개념 학습"(개념 수, 평균 숙련도), "AI 모의 면접" | 목록 / 면접 홈 |
| 오늘의 퀴즈 | 오늘 안 풀었으면 "아직 안 풀었어요" + 풀기 버튼. 풀었으면 "오늘 완료 · 2/3 정답" + 결과 보기 | 퀴즈 |
| 오답노트 | 풀어야 할 오답 수 | 오답노트 |
| 오늘 복습 | 복습일이 된 개념 수 | 목록 ("오늘 복습" 칩이 선택된 상태) |

- 화면이 다시 보일 때마다(`onResume`) 통계를 다시 읽는다. 퀴즈를 풀고 돌아오면 바로 갱신돼야 하기 때문이다.
- 면접 기록이 없으면 히스토리 카드는 "아직 면접 기록이 없어요 · 첫 면접 해보기" 로 바뀐다.
- 데이터: `DailyQuiz`(오늘 행이 있고 완료됐는지), `WrongAnswer`(resolved = false 개수), `ConceptProgress`(nextReviewAt ≤ 오늘), `InterviewRecord`(최근 1건, 전체 개수, 최근 점수 5개).

## 4. CS 개념 학습 - 목록

- **구성**: 상단에 "오늘의 퀴즈 (3)", "오답노트 (7)" 버튼 두 개. 그 아래 카테고리 칩 줄, 선택한 카테고리와 개수, 정렬, 개념 목록.
- **카테고리 칩**: "전체", "오늘 복습", 10개 카테고리(자료구조, 알고리즘, 운영체제, 네트워크, DB, Java/Kotlin, 웹/백엔드, 보안, 설계/패턴, 안드로이드). 가로 스크롤, 하나만 선택. 처음에는 "전체". 퀴즈를 마친 날 퀴즈 버튼은 "오늘의 퀴즈 ✓" 로 바뀐다.
- **정렬**: 기본순(카테고리 안 순서) / 숙련도 낮은 순 / 복습일 빠른 순.
- **항목**: 제목, 한 줄 요약, 별, Lv, 숙련도 막대, 복습 상태. 복습일이 지났거나 오늘이면 빨간 "복습 오늘", 아니면 "N일 뒤", 아직 안 봤으면 "아직 안 봄".
- **빈 상태**: "오늘 복습" 칩인데 대상이 없으면 "오늘 복습할 개념이 없어요".
- **구현**: `RecyclerView`. 개념 60개 전체를 메모리에 올려 두고 칩에 따라 걸러 보여 준다.

## 5. CS 개념 학습 - 상세

- **구성(위에서 아래로)**: 카테고리 칩 · 별/Lv · 다음 복습일 → 한 줄 요약 → 키워드 칩 → 설명 본문 → 면접 단골 질문 2개 → 이전/다음 개념.
- **단골 질문**: 질문을 누르면 "모범 답안 예시"가 펼쳐지고 다른 질문은 접힌다. 처음에는 첫 질문만 펼친다.
- **이전/다음 개념**: 같은 카테고리 안의 순서로 이동한다. 첫 개념에서는 "이전"을, 마지막 개념에서는 "다음"을 비활성으로 한다.
- 개념을 처음 열면 `ConceptProgress.studiedAt` 만 기록한다. 숙련도는 퀴즈로만 바뀐다.

## 6. CS 개념 학습 - 퀴즈

### 출제
- 하루 3문제. 처음 들어온 날짜에 문제 3개를 정해 `DailyQuiz` 에 저장하고, 중간에 나갔다 와도 같은 문제를 이어 푼다.
- 개념 하나에서 한 문제만 낸다. 개념 고르는 순서는 ① 복습일이 지난 개념(오래된 순) ② 미해결 오답이 있는 개념 ③ 숙련도 낮은 순, 미학습 포함. 개념 안에서는 최근에 안 푼 문제를 고른다.
- 보기 순서는 콘텐츠에서 한 번 섞여 있고, 앱에서는 정답 번호를 따로 들고 있다가 채점한다.

### 풀이 화면
- 상단: 중단(✕), 제목, 진행(2/3), 진행 막대. 문제 번호 아래에 카테고리와 개념 이름.
- 보기를 누르면 즉시 채점된다. 내가 고른 보기는 정답이면 초록, 오답이면 빨강, 오답일 때 정답 보기는 초록으로 같이 보이고 해설이 나온다. 채점 뒤에는 보기를 바꿀 수 없다.
- 하단 버튼은 채점 전에는 비활성, 채점 뒤에 "다음 문제"(마지막 문제는 "결과 보기").
- 중단: "그만하면 지금까지 푼 문제까지만 반영돼요" 확인 후 홈으로. 다시 들어오면 푼 다음 문제부터 이어진다.

### 숙련도 반영 (문제 단위, DESIGN 4.1 변경)
| 결과 | 숙련도 | 다음 복습 |
| --- | --- | --- |
| 정답 | +1 (최대 Lv.5) | Lv.1 → 1일, Lv.2 → 2일, Lv.3 → 4일, Lv.4 → 7일, Lv.5 → 15일 뒤 |
| 오답 | −1 (최소 Lv.1) | 같은 규칙. 오답노트에 추가 |

- 미학습(기록 없음)은 Lv.0 으로 보고, 처음 푼 개념은 정답이면 Lv.1, 오답이어도 Lv.1 로 시작한다.

### 결과 화면
- 점수(2/3), "내일 새 퀴즈가 열려요", 문제별 정오 + 개념 이름 + 숙련도 변화 + 다음 복습일. 오답은 "오답노트에 추가됨" 표시.
- 버튼: "오답노트 보기", "홈으로".
- 오늘 이미 풀었다면 퀴즈로 들어갈 때 결과 화면이 바로 열린다. 추가 세트는 제공하지 않고, 더 연습하려면 오답노트의 "다시 풀기"를 쓴다.
- 날짜가 바뀌는 시각은 자정(기기 시간).

## 7. CS 개념 학습 - 오답노트

- **구성**: 위쪽에 "풀어야 할 것 / 해결함" 두 탭(개수 표시), 카테고리 칩, 오답 목록, 하단 "오답 다시 풀기 (N)".
- **항목**: 카테고리, 몇 번 틀렸는지, 문제, 내가 고른 답(빨강)과 정답(초록), "해설 보기"(펼침), "개념 보기"(상세로).
- **다시 풀기**: 현재 탭과 카테고리 칩에 걸린 오답 중 최대 10문제를 퀴즈 화면으로 푼다. 맞히면 `resolved = true` 가 되어 "해결함" 으로 옮겨 가고, 틀리면 틀린 횟수만 늘어난다. 이 모드에서는 숙련도를 바꾸지 않는다. 오답을 낼 때 이미 내렸기 때문이다.
- 해결한 문제를 일일 퀴즈에서 다시 틀리면 "풀어야 할 것" 으로 돌아온다.
- 빈 상태: "오답이 없어요. 퀴즈를 풀어 볼까요?" + 퀴즈 버튼. 이 화면에서는 삭제를 제공하지 않는다(해결함 탭에 쌓이는 것으로 충분).

## 8. AI 모의 면접 설정

모든 항목은 선택 입력이고, "저장"을 눌러야 반영된다. 저장하면 면접 홈으로 돌아간다. 화면을 그냥 나가려는데 바뀐 내용이 있으면 확인을 받는다.

| 항목 | 입력 | 규칙 |
| --- | --- | --- |
| GitHub 레포 URL | 한 줄 + [분석] 버튼 | `https://github.com/{owner}/{repo}` 형식만 받는다. 아니면 입력칸 아래에 오류 문구. |
| 분석 상태 | 미분석 / 분석 중 / 완료 / 실패 | 분석 중에는 스피너와 "몇 분 걸릴 수 있어요. 화면을 나가도 계속돼요". 완료되면 기술 스택과 예상 질문 수. 실패는 이유와 [다시 분석]. URL 을 바꾸면 이전 결과가 지워진다. |
| 채용 공고 | 회사명, 직무, 공고 본문(붙여넣기, 최대 5,000자) | 본문은 글자 수를 보여 준다. 링크를 넣어도 서버가 읽어 오지 않으므로 "내용을 복사해 붙여넣으세요" 라고 안내한다. |
| 이력서·포트폴리오 | 파일 선택(PDF, TXT, 5MB 이하) 또는 직접 입력 | 파일을 고르면 파일 이름 칩(✕ 로 제거). PDF 는 서버가 글자를 뽑는다(12장). 파일과 직접 입력이 둘 다 있으면 직접 입력을 우선한다. |
| 기타 요청 | 여러 줄, 최대 500자 | 예: "프로젝트 위주로", "압박 면접으로", "동시성 질문 포함". 면접관 프롬프트에 그대로 들어간다. |
| 면접 유형 | CS / 지원서 / 혼합 | 기본 혼합. 지원서·혼합인데 공고·이력서·GitHub 가 모두 비어 있으면 저장 때 "입력한 정보가 없어 CS 질문 위주로 진행돼요" 안내. |
| 주제 수 | 1~10 (기본 5) | |
| 주제당 꼬리질문 | 0~3 (기본 2) | |
| 답변 방식 | 텍스트 / 음성 | 음성을 고르면 처음 한 번 마이크 권한을 요청한다. |

- 설정은 한 세트만 저장한다(여러 지원서 관리는 이번 범위 밖, 12장).

## 9. AI 모의 면접 홈

- **구성**: 서버 상태, "내 지원 정보" 카드, "이번 면접 옵션" 한 줄, 면접 시작 버튼, 바로가기(면접 설정, 면접 히스토리), 최근 리포트.
- **지원 정보 카드**: 항목별 한 줄. GitHub(분석 완료·분석 중·미입력·실패), 채용 공고(회사 / 직무), 이력서·포트폴리오(파일 이름 또는 "미입력"), 기타 요청(있음 / 없음). 카드 전체 또는 "설정 ›" 를 누르면 설정으로.
- **면접 시작**: 서버가 연결돼 있으면 활성. 입력이 하나도 없어도 시작할 수 있고, 이때는 아래에 "일반 질문이 늘어납니다" 안내를 보여 준다. GitHub 분석이 아직 진행 중이면 "분석이 끝나지 않았어요. 기다릴까요, 분석 없이 시작할까요?" 를 묻는다.
- **서버 꺼짐**: 상단 배너 "서버에 연결할 수 없어요 · PC 서버가 켜져 있는지 확인하세요" + [다시 확인]. 시작 버튼은 비활성.
- 진행 중이던 면접을 이어 하는 기능은 두지 않는다. 서버 세션이 메모리에 있어 앱이 종료되면 사라진다(DESIGN 9장).

## 10. AI 모의 면접 진행

### 화면
- **상단**: "주제 2/5 · 꼬리질문 1/2", 오른쪽 [종료]. 서버가 `type` 을 정해 주는 대로 갱신한다.
- **본문**: 채팅 목록. 면접관 말풍선(왼쪽, "다시 듣기")과 내 말풍선(오른쪽). 음성 답변은 인식된 텍스트가 말풍선으로 들어간다.
- **하단**: 답변 방식에 따라 다르다.
  - 텍스트: 입력창 + 보내기. 빈 입력은 비활성.
  - 음성: 아래 상태 흐름.

### 음성 답변 상태 흐름
| 상태 | 화면 | 다음 |
| --- | --- | --- |
| 질문 읽는 중 | 면접관 말풍선, 스피커 표시. 마이크 버튼 비활성 | 읽기가 끝나면 대기 |
| 대기 | "눌러서 답변하기" 마이크 버튼, "텍스트로 입력" 링크 | 버튼 누르면 녹음 |
| 녹음 중 | 파형, 경과 시간, 빨간 "완료" 버튼. 110초가 되면 "곧 종료돼요" 표시, 120초에 자동 종료 | 완료 누르면 인식 |
| 인식 중 | "답변을 정리하고 있어요" | 텍스트가 말풍선으로 들어가면 생각 중 |
| 면접관 생각 중 | 점 세 개 말풍선 | 다음 질문이 오면 질문 읽기 |

- 1초보다 짧은 녹음은 버리고 "다시 말씀해 주세요" 를 보여 준다.
- 녹음은 탭으로 시작하고 탭으로 끝낸다(DESIGN 4.3 의 "누르는 동안 녹음" 에서 변경, 12장).
- "텍스트로 입력" 을 누르면 그 질문만 텍스트로 답할 수 있다. 이 답변은 음성 지표에서 빠진다.

### 종료와 오류
- [종료] 와 뒤로가기는 같은 확인을 연다: "계속하기 / 종료하고 리포트 보기 / 기록 없이 나가기".
- 서버가 `type = end` 를 주면 "면접이 끝났어요. 리포트를 만들고 있어요 · 약 20초" 로딩 화면 → 리포트.
- 서버 오류·타임아웃: 해당 턴에 "다시 시도" 버튼. 보낸 답변과 녹음 파일은 성공할 때까지 들고 있다.
- 마이크 권한 거부: "텍스트 모드로 전환할까요?" 확인 후 이 면접을 텍스트 모드로 바꾼다.
- 면접 중에는 화면이 꺼지지 않게 한다.

## 11. AI 모의 면접 결과 리포트 / 히스토리

### 11.1 리포트
- **머리**: 날짜, 유형, 방식, 총점(원형), 총평. 아래에 탭 세 개: 종합 / 질문별 / 음성.
- **종합**: 강점, 개선점, 점수가 낮았던 개념(→ 개념 상세, "공부하기"). 하단 버튼 "히스토리", "한 번 더 면접"(설정을 유지한 채 면접 홈으로).
- **질문별**: 질문마다 카드. 주제, 질문, 내 답변(꼬리질문은 이어서), 별점, 피드백, "모범 답안"(접힘).
- **음성**: 사용자가 요청한 네 가지를 카드 하나씩으로 보여 준다.

| 카드 | 보여 주는 값 | 서버 지표 (DESIGN 4.3) |
| --- | --- | --- |
| 목소리 | 평균 음량, 끝으로 갈수록 작아졌는지 | 음량(RMS 평균, 변화폭) |
| 발성 | 분당 음절 수, 멈춤 횟수, 군말 횟수 | 말 속도, 멈춤, 군말 |
| 발음 | 알아듣기 쉬운 정도 0~1, 인식이 낮았던 단어 | Whisper 단어 신뢰도 평균. "참고값" 이라고 표시 |
| 문맥 | AI 코멘트 한두 문장 | 문장(두괄식, 길이, 반복) |

- 카드마다 상태 글자(좋음 / 보통 / 개선)와 기준 범위 띠 위에 내 값 표시를 둔다. 기준 안이면 좋음, 조금 벗어나면 보통, 크게 벗어나면 개선이다. 기준 값은 DESIGN 4.3 의 초안을 쓰고 시험하며 조정한다.
- 맨 아래에 답변별 말 속도 막대 그래프. 라이브러리를 쓰지 않고 `View` 높이로 그린다.
- 텍스트로 진행한 면접은 음성 탭에 "텍스트로 진행한 면접은 음성 지표가 없어요" 와 "음성으로 다시 면접" 버튼만 둔다. 일부 답변만 텍스트였다면 그 답변은 지표에서 빠지고 "N개 답변 기준" 이라고 적는다.
- 리포트를 만들다 실패하면 면접 기록은 먼저 저장해 두고 "리포트 만들기 다시 시도" 를 보여 준다.

### 11.2 히스토리
- **구성**: 점수 변화 선 그래프(최근 10회), 유형 칩(전체 / CS / 지원서 / 혼합), 리포트 목록.
- **항목**: 점수, 제목(면접 때의 회사 / 직무, 없으면 "CS 기초"), 날짜, 유형, 방식. 최신순. 탭하면 11.1 화면을 저장된 내용 그대로(읽기 전용) 연다. 길게 누르면 삭제 확인.
- **빈 상태**: "아직 면접 기록이 없어요" + 면접 홈으로 가는 버튼.

## 13. 정해야 할 것

1. **"기타 질문" 해석**: 6번 항목의 "기타 질문" 을 "꼭 받고 싶은 질문이나 요청을 자유롭게 적는 칸" 으로 만들었다. 다른 뜻이었다면 알려 주세요.
2. **퀴즈 추가 세트**: 하루 한 세트만 허용하는 안으로 썼다(통계의 "오늘 풀었는지" 가 분명해진다). 더 풀 수 있게 하려면 세트 횟수 규칙이 필요하다.
3. **음성 인식 결과 수정**: 잘못 알아들은 텍스트를 사용자가 고칠 수 있게 할지(DESIGN 7장에 미정으로 남아 있다). 이 문서는 수정 없이 바로 진행하는 안이다.
4. **화면 구현 방식**: Activity 10여 개로 갈지, Activity 하나에 Fragment 로 갈지(수업에서 쓴 방식에 맞춘다).
5. **지원 정보 한 세트 vs 여러 개**: 회사별로 여러 개를 저장하려면 면접 홈에 "지원서 선택" 이 필요하다.
